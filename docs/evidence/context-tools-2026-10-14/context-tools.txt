game_author_briefing()
============================================================
GAME TYPE
Watchtower recovery is a story-led 2D top-down action/RPG prototype.

SETTING
A small fantasy watchtower, its courtyard and two ridge beacons. No magic system or dungeon mechanics are currently implemented.

STORY AND CONTEXT
The watchtower needs recovery. Sentries occupy the courtyard; a watchkeeper offers a choice of coloured seals. Blue belongs at Beacon A and red at Beacon B. No larger world history, factions or supernatural conflict have been established.

YOUR ASSIGNMENT
Invent a coherent short quest, motivations and dialogue using the supported world references and mechanics. Give choices understandable reasons and consequences. Do not invent executable capabilities, entities or established world history. Publication does not start gameplay.

GAME MECHANICS
WASD moves; Shift runs. E or a nearby click interacts within 42 pixels. Combat in this prototype is one interaction to defeat a revealed sentry. Revealed seals can be collected and carried to their matching beacon. Delivery consumes custody but lighting is a separate quest consequence. The watchkeeper must be revealed and within 48 pixels for guarded choices. A closed ridge gate blocks its rectangle but can be walked around.

SUPPORTED GAME PRIMITIVES
- game_location (inspection): Inspect whether the protagonist is inside or has visited a location; count entries for new-event conditions.
- game_encounter (inspection): Inspect remaining enemies in a group; count confirmed defeats. The protagonist defeats enemies through ordinary interaction, not an authoring action.
- game_entity (inspection): Inspect proximity, visibility and collection state of an entity; count confirmed pickups.
- game_activate_group (action): Reveal undefeated enemies in an existing group when entering a quest stage.
- game_reveal (action): Reveal an existing entity unless it was already defeated or collected.
- game_open_gate (action): Open an existing gate as a quest consequence.
- game_light_beacon (action): Light an existing beacon as a quest consequence; this does not itself deliver an item.
- game_delivery (inspection): Inspect whether a specific item reached its matching destination; count confirmed deliveries.

BEFORE AUTHORING
You must gather context before creating a quest. You can:
- Review confirmed game events (game_journal_read).
- Inspect current world and quest status (game_status_read).
- List characters, items, locations, spawn locations and buildings, filtering known/unknown to the protagonist (game_entities_list).
- Read details of an exact reference (game_entity_details).
- Verify map accessibility (game_location_accessibility).
- Calculate straight-line or navigable-route distances (game_distance).
- Read executable capability schemas (read_quest_draft, section catalogue).
