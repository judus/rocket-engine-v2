# Factory in streamed terrain

`factory-terrain.html` is a separate integration demo. It reuses the installed Workshop 2.0.0 dependency, classic tile/decorations adapter and bounded chunk stream. It does not modify existing saved terrain or introduce transport. Normal mode now has a separate versioned factory checkpoint.

## Ownership

The page owns one `FactoryDemo`, one placement registry initialized with three authored buildings and one in-memory terrain edit store. Workshop owns its three facilities and single stockpile. Initial placements associate the stable facility IDs with tile cells `(4,4)`, `(12,4)` and `(20,4)`. These are authored demo placements, not a construction/terrain suitability system. No inventory lives in a building visual or chunk.

`FacilityVisuals` is a presentation cache. It creates a building record only after that cell has prepared classic artwork; loading neighbor dependencies can delay its appearance. The record stores a facility ID, immutable placement and a per-cache incarnation counter. Its draw function reads a detached Workshop state. Building and vegetation draws share world-feet ordering through the classic cache's optional drawing objects.

Eviction removes the record without removing a facility. Return creates a new record for the same facility ID. The terrain view owns demand, input binding, two image leases, classic artwork, shaping/decoration data and building visuals. Closing it releases those resources; the diagnostic canvas remains and production continues. Recreating views disposes the previous app and stream while retaining the page-owned Workshop and placement table. It resumes the app and excludes the recreation gap from simulation time. Page teardown finally disposes Workshop's coordinator and event subscription.

## Time and bounded work

One scene update forwards full visible elapsed time to Workshop, independently of camera position, chunk readiness and terrain-view lifetime. Workshop stops only for manual pause, hidden tabs, app recreation gaps and final page teardown. It can block naturally when storage is full. Collection withdraws finished parts through the existing Workshop command. No offline progression, dormant simulation policy or second production clock is introduced.

The world has at most 224 retained chunks and eight async job slots. The simulated loading delay is disabled (0 ms); generation still runs through asynchronous timer callbacks. Chunks appear progressively without a loading screen. One terrain demand owner covers one extra artwork ring around the camera plus sprite overhang; the stream retains another neighbor ring for autotile dependencies; the diagnostic view owns no terrain demand. Classic preparation builds at most four artwork regions per update, stopping before another build once its 3 ms soft time budget is exhausted (a single synchronous region build can exceed that budget) and requires ready neighboring chunks. Object and raster caches are pruned on departure and rebuilt on return. These are bounded work counts and a soft budget, not a hard frame-time guarantee.

The terrain canvas is 1280 × 720 pixels, showing 80 × 45 tiles at native 16-pixel scale: four times the original viewport area. Diagnostics remain 640 × 460. The page stacks the views to give terrain the full available width; narrow windows scale the displayed canvas while retaining its full render resolution.

Camera velocity eases toward input with a roughly 83 ms response time; position uses the analytic integral so the motion agrees across frame rates. Release coasts briefly, and teleport/pause reset velocity.

The frame selector supports uncapped, 100, 80, 60 and 30 FPS. Rocket skips complete update/render passes until a cadence deadline, keeps full elapsed simulation time, and never replays missed renders. Visibility and stop reset deadlines. Actual presentation is quantized to browser refresh callbacks; limits that do not divide the display refresh can introduce uneven intervals. Diagnostics include average and maximum frame intervals over each half-second window plus update/render work.

Camera movement matches the other terrain demo at 32 tiles per second (512 pixels per second). Artwork is prepared ahead of the viewport so normal travel does not wait for the entering row’s neighbors. Initial loading and distant jumps still show loading placeholders.

Controls expose the lifecycle: Visit far away records the departure Workshop tick; Return restores the factory camera; Close terrain reaches zero visuals while facilities survive; Recreate views reports previous resource counts and keeps production stock/time. Manual pause disables commands until resumed. Normal-mode reload restores the last explicit factory checkpoint; stress mode still starts fresh.

## Validation

Integration tests evict the factory's home chunks, release all three visuals, advance production away, return with new visual incarnations and the original facility IDs, then recreate presentation records without changing stock or domain state. They also verify that pending/missing visuals and disposal have no production authority and that presentation reads do not advance simulation. A regression check crosses a northern boundary at negative coordinates with no new loads or artwork builds, and verifies that every visible cell already has artwork. Alignment checks keep the expanded demand within the chunk cap. Existing tests cover the Workshop clock bridge, blocking, input shortages, view removal and the streamed classic halo/invalidation contracts.

Browser checks inspect initial delayed loading, travel with zero visuals/three facilities, return, terrain closure and recreation. Strict TypeScript, type-aware lint, formatting and emitted-JavaScript checks remain required. Physical logistics and large-world dormant simulation are subsequent steps.

## Frame spike investigation

The demo starts uncapped and retains only the last 12 slow samples, with a 32-interval cadence window. It records a callback gap over 1.5 times recent median cadence (minimum 12 ms), or measured work over 8 ms. Capped runs use the configured interval as the cadence reference. A sample associates the gap with the preceding frame’s measured work and intervening timer-driven generation, rather than blaming work that runs after the late callback arrives. Pause/visibility zero-delta frames and frame-limit changes reset pending timing; view recreation disposes the old recorder. Clear history drops retained samples.

Generation measures the source generator callback, excluding artificial network-like delay. Scene work comprises Workshop advancement/snapshot, camera/demand, visual updates and HUD. Stream publication and artwork preparation are separate, non-overlapping phases; artwork includes shaping, raster construction and decoration generation. Render measures both scene draw callbacks, including decoration sorting, but excludes engine view setup and GPU/compositor completion. Counts show generated chunks and built artwork regions. Timings are synchronous wall-clock measurements, not pure CPU utilization. Unmeasured gap time includes normal refresh waiting, uninstrumented work, callback scheduling and presentation; it cannot identify garbage collection. This is diagnostic evidence, not a conclusion that the stutter is fixed.

## Draw culling

Classic object draws query only cached chunks in the camera footprint plus catalog sprite overhang (three tiles horizontally and seven below). Individual decoration bounds are then tested against the viewport. Artwork prefetch regions outside that footprint are retained without scanning their decoration records. Facility visuals provide world-pixel bounds including the 62-pixel roof height and 30-pixel half-width; their draw callbacks are skipped when those bounds do not intersect the viewport. This changes draw visibility, not visual ownership or Workshop state. All surviving decorations and facilities share one depth sort by feet, x and stable ID. Diagnostic counters show queried regions, scanned versus retained decoration records, and visible depth objects from the previous draw. Regression checks cover signed coordinates, exact edge exclusion, roof and cross-chunk tree overhang, depth ties, skipped prefetch records and disposal.

## Camera presentation A/B

Camera rendering can switch live between Fractional (default) and Pixel-snapped. Snapping rounds only the final shared camera translation to integer backing-canvas pixels after applying pixel ratio and zoom. Camera state, inertia, simulation, demand and culling remain precise. Trees, cached ground and facilities share the same snapped transform; the diagnostic view remains fractional. View picking compensates for the presentation offset so pointer coordinates still match the rendered map. This does not impose integer sprite scaling or remove browser CSS/compositor resampling, and it does not fix late frames. Recreating views retains the selector’s choice.

## 6,000 facility stress mode

Open `factory-terrain.html?stress=6000&range=128`. It creates 2,000 independent mine/smelter/press chains: 6,000 Workshop facilities and 6,000 inventories with initial inputs and capacity 1,000,000 per material. All facilities run on the main thread regardless of terrain demand. This follows the Workshop workload structure but retains this demo’s recipes and bulk parts; it does not reproduce the original individual-item worker benchmark. Output can eventually fill storage; this is not an indefinitely bounded stock sink or a worker benchmark. UI stock and collection show only the first chain’s finished inventory, while completed parts counts all presses.

Seed 42 samples unique tile anchors within ±128 tiles of the starting world origin `(0,0)`. `range` accepts an integer radius of 40–512 tiles. Placement does not reject water or overlapping building footprints. A static signed chunk index queries nearby placements; only artwork-ready presentation IDs are snapshotted each frame. Rendering uses ID-map lookups instead of a linear snapshot search for each building. Terrain retention, jobs and draw culling remain bounded independently of the full factory population. Far travel, closing terrain and recreating views preserve all domain facilities; reload creates a fresh deterministic run. Normal three-building mode retains its original shared stockpile and capacities.

The stress regression checks all 6,000 jobs initially producing, exact facility/inventory counts, unique deterministic signed placements, spatial query bounds, production while all visuals leave, stable IDs on return, bounded event history and continued simulation after presentation disposal. Browser results are short interactive observations, not a sustained benchmark.

## Interactive construction

Normal mode has a Build selector with Pan, Mine, Smelter and Press. The pointer previews a 3 × 2 tile foundation centered horizontally on its tile anchor, ending at the building’s feet. All six foundation cells require prepared artwork and displayed land (atlas tiers above 2). Missing/pending terrain, displayed water and overlapping occupied foundations reject placement before any Workshop command. Roof overhang, trees, slope suitability, removal and material costs are not construction constraints in this slice. Preview is a world-space overlay, colored green/red, with a textual reason. Pan mode only focuses camera input.

A successful primary-pointer press issues one Workshop add-facility command using the existing shared stockpile, obtains its stable ID, reserves the foundation and adds a presentation record to the signed chunk index. Repeated clicks on occupied ground do not create facilities. New presses contribute to the aggregate completed-parts counter. Construction and occupancy belong to the page and survive visual eviction, closure and view recreation. Pointer bindings, preview and view-owned presentation are recreated; construction is disabled during pause, terrain closure and stress mode. Normal mode can now save and restore construction with production as described below. No transport is introduced.

Tests cover every footprint cell, signed boundaries, water/loading rejection, failed creation without occupancy mutation, touching versus overlapping foundations, multiple presses in one stockpile, stable IDs and occupancy after eviction/recreation, and stress-mode rejection. Browser checks build a Press, reject water and repeat placement, then evict and recreate presentation.

## Explicit factory checkpoints

Save factory writes one version-4 `rocket-factory` record in a separate `rocket-v2-factory` IndexedDB database (`checkpoints`, key `normal-w2-v4`). It captures Workshop save state, advances/completed/collected host counters, stable building IDs and tile anchors, generator version/seed/scale and classic presentation identity. Workshop owns jobs, stock, reservations, deterministic outcomes, pending fractional time and next IDs; caches, inputs, camera, manual pause and recent event logs are not saved. Occupancy is derived from foundations on restore, labels from facility definitions. At most 10,000 normal buildings are supported per checkpoint. Existing terrain edit databases are untouched. Stress mode does not open factory storage or save its 6,000-facility population.

Save snapshots synchronously at a simulation-safe event boundary; storage clones that snapshot before awaiting a database open. Production can continue while one write is pending, and Save is disabled until completion. Success means the transaction committed, not merely that a request succeeded. Status reports the saved tick and explains that subsequent changes are unsaved. Failure retains the previous checkpoint and live memory world for another explicit Save. There is no autosave, shutdown-save promise or offline progression. Reload resumes the saved point, ignoring wall-clock time spent away. Manual pause can be used to save a stable inspection point, but reload resumes production.

Startup reads and validates the whole record before composing views or advancing production: format/version, generator/presentation compatibility, Workshop configuration/state, normal inventory layout, counters, placement coordinates, exact ID coverage and non-overlapping foundations. Failed/incompatible loading blocks startup and offers Retry load; it never silently starts an empty world or overwrites the unreadable record. No saved record starts the ordinary initial factory. Storage handles blocked/unavailable IndexedDB and version-change closure. Page teardown closes connections and aborts outstanding work; view recreation keeps the page-owned save store and world. The demo has one origin-local checkpoint slot; multiple tabs have last-committed-writer behavior, not conflict detection.

Tests verify mid-batch jobs, pending time, stock, counters, stable IDs/next IDs, derived occupancy, deterministic continuation, complete-record rejection, detached writes, commit/abort behavior, failed-write retry, reopen/reload, untouched malformed records and disposal during open. Browser verification built a fourth Press, saved tick 792 with 18 produced/collected parts, reloaded the checkpoint and resumed all four facilities.

## Timed transport mode

Open `factory-terrain.html?transport=1`. This mode preserves the existing shared-stockpile demo and its save. Each facility instead has a private input and output buffer of capacity 20, plus the empty construction inventory: the initial three-building chain has seven inventories. Mine → Smelter ships up to two ore; Smelter → Press ships one alloy. The initial routes take two seconds. Newly built facilities require a compatible Source/Destination link; Connect computes straight-line travel at 64 world pixels/second, minimum 0.5 seconds, rounded up to whole 50 ms production ticks. One supplier route per destination and one active cargo packet per route keep jobs bounded. Routes do not model roads, vehicle return trips, collisions or terrain obstacles.

Workshop reserves source goods and owns pickup, cargo, inbound demand promises and destination unloading. The host stores endpoints and departure/arrival ticks. For transport mode only, elapsed time is segmented at Workshop tick boundaries so each production tick is followed by due arrival attempts, then demand-driven dispatch. Failed unloading keeps arrival-blocked cargo for retry on later ticks. Least-recently-dispatched routes receive first access when consumers share a source; that priority timestamp is checkpointed. Terminal Workshop deliveries are pruned after route completion; active deliveries are retained. No second wall clock, timer-driven delivery job or draw mutation is introduced. Production and transport run with no terrain demand owner. Bulk parts can be collected from all Press outputs; displayed stored materials aggregate buffers and exclude in-transit goods.

Orange ore and blue alloy markers interpolate using Workshop tick plus pending time between stable placement anchors; red indicates blocked unloading. Markers join buildings/vegetation in the same culled depth ordering. They can appear over terrain placeholders because cargo visibility does not own or gate simulation.

Version-4 transport checkpoints store the same Workshop state and placements plus route definitions, active delivery IDs, departure/arrival deadlines, completion counts and scheduling priority. They use `transport-w2-v4` in the existing checkpoint store, separately from `normal-w2-v4`. Validation checks mode/version, private inventory endpoints, compatible recipes, one supplier per destination, cargo quantities/ownership, unique active delivery IDs and complete coverage of Workshop cargo. Only the current version-4 envelope with Workshop save version 4 is accepted. Old slots are not read, converted or migrated. Shared/transport modes have distinct current slots, not alternate compatibility loaders. Reload excludes offline progression and resumes in-flight cargo.

Tests cover pickup ownership, no early arrival, separate buffers, bounded/pruned deliveries, frame-partition agreement (allowing sub-nanosecond pending-time floating-point differences), fair shared suppliers, draw-only markers, view eviction, new facilities, in-flight save/restore and slot isolation, invalid deadlines/orphaned cargo, and blocked unloading/restoration/retry. Browser proof added a fourth Press, connected a 7.8-second route, saved tick 3800 with three routes and active cargo, then restored the same population, counters and delivery state. All 157 tests pass.

## Inspection, route disconnection and guarded removal

Normal and transport modes now expose a building inspector. Select an ID or click its 3 × 2 foundation in Pan mode. The inspector reads Workshop job state, buffers and incident routes; it neither advances nor owns production. Drain/Resume uses Workshop's `setFacilityDraining`: existing work can finish, but draining prevents new starts. Output-blocked work may still need collection.

Disconnect stops dispatch immediately. A route with cargo stays in a draining state until unloading succeeds; blocked cargo keeps ownership and retries. A route without cargo disappears immediately. Draining routes and active cargo survive checkpoints; a replacement supply route cannot be connected until the old one has finished.

Building removal is explicit, never an automatically scheduled deletion. Workshop removal blockers and any incident active cargo block it. In transport mode, input/output materials transfer to the shared stockpile before removal; a capacity preflight refuses the complete operation if they do not fit. No goods are discarded. Collect includes salvaged parts. Removed Press history stays in Workshop's retired-facility ledger, so lifetime production counters remain valid after save/restore. Shared-stock mode preserves other facilities' work and reservations.

After successful domain removal, page-owned construction releases the footprint and the view releases its visual record and spatial bucket membership. Closed views require no visual mutation; recreation reads the remaining placement list. Newly built facilities receive new Workshop identities and new private buffer names.

**Workshop boundary:** after its guarded facility removal, Rocket calls Workshop 2.0.0 `removeInventory` for each empty private buffer. Workshop validates inventory references and performs retirement; Rocket does not rewrite saves or duplicate inventory state. Buffer names use a saved monotonic host counter, independent of active inventory count, so removal does not reuse an active identity. Only live buffers remain; Workshop's retired-facility provenance is still retained, so total historical churn is not claimed to be bounded. Selection is presentation state and is not saved.

## Camera-service integration

All factory terrain modes (shared stock, transport and 6,000-facility stress) now bind the optional Cameras service to the terrain view. Diagnostics retains its fixed independent camera. The factory preserves its 512 logical pixels/second pan speed with inertia; screen speed remains consistent across zoom. Wheel zoom anchors beneath the cursor and stepped zoom anchors at the viewport center. Camera pose is presentation state, not part of the factory checkpoint.

The 1280 × 720 view supports 0.75–4× zoom within the existing 224-chunk/8-job budget. Below 1×, optional artwork prefetch is removed; sprite overhang demand and terrain dependency neighbors remain. At 1× and above, the original one-chunk artwork prefetch stays enabled. At 0.75×, approximately 78% more world area is visible than at 1×. A smaller zoom would require a separate capacity or viewport policy.

Draw bounds, object culling, artwork preparation and streaming demand derive from the rendered four-corner `View.worldBounds`, using signed tile floor/ceil. Before camera update, the input-time world pointer is converted back to logical screen coordinates; afterward it is repicked through the new view inverse. Placement preview, construction and foundation inspection therefore use the current camera, including CSS scaling, fractional zoom and translation snapping.

Closing terrain disposes the controller/wheel listener and demand but keeps Workshop and diagnostics running. Recreate binds a fresh controller and reports zero old controllers alongside the existing cleanup counters. Pause stops/reset motion and pending wheel input; zoom controls are disabled while paused/closed. Travel commands reset motion, and Return also restores 1× zoom. Camera state does not alter simulation authority; the current factory save contract is described above.

Validation: all 166 checks pass. Factory demand tests exercise every signed chunk alignment at the minimum zoom, just below/above the prefetch transition, and larger zoom levels. Picking checks cover zoomed/snapped foundations, occupied previews and creation at the visible cell. Browser verification selected the Smelter at 0.75×, exercised pan/wheel zoom, and observed demand shrink while production continued.

## Workshop 2 checkpoint reset

Both modes use one factory checkpoint envelope (version 4), an explicit required mode, required route/draining state, a monotonic buffer counter and Workshop save format 4. The current storage keys are `normal-w2-v4` and `transport-w2-v4`. Previous demo slots are intentionally ignored; fresh demos start with the initial factory until explicitly saved in the current slot. There are no migrations, legacy field defaults or fallback implementations. Malformed records in a current slot still fail visibly without overwriting them.

Timed construction, cancellation, workplace attendance and per-building production pause are now demonstrated in the opt-in Workshop profile. Basic profiles retain their small free-placement configuration. The current checkpoint represents active sites and requires an explicit Workshop profile field; it has no legacy defaults. See [construction and staffing contracts](WORKSHOP-FEATURES.md). The feature profile has its own `workshop-w2-v4` slot.
